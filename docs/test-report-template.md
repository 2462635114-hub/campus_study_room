## 3. 测试运行方式

### 3.1 环境准备

```powershell
cd C:\Users\Lenovo\Desktop\deepseek\campus_study_room
python -m pip install -r requirements.txt
```

### 3.2 运行全部自动化测试

```powershell
cd C:\Users\Lenovo\Desktop\deepseek\campus_study_room
python -m pytest -q
```

> 说明：`pytest.ini` 已配置 `testpaths = tests`、`pythonpath = .`、`addopts = -ra`。测试夹具使用临时数据库，**不会**读写 `instance/campus.db`；`TestingConfig` 中 `WTF_CSRF_ENABLED = False`，因此表单测试不需要 CSRF 令牌。

### 3.3 运行单个测试文件 / 单个用例（按需）

```powershell
python -m pytest tests\test_auth.py -q
python -m pytest tests\test_auth.py::test_login_success -q
```

### 3.4 集成冒烟检查（不依赖 pytest，验证页面渲染与关键链路）

```powershell
python scripts/smoke_check.py
```

### 3.5 结果输出要求

- 若需要留存原始输出文件，可使用（PowerShell 重定向）：

```powershell
python -m pytest -q *> test-output.txt
python scripts/smoke_check.py *> smoke-output.txt
```

- 报告附件建议：`test-output.txt`、`smoke-output.txt`、失败用例截图、缺陷复现录屏（如有）。

## 7. 并发测试说明（TC-CONC-01 执行方法）

1. 准备：两个独立测试客户端（或两个线程），同一应用/数据库，预置同一自习室、同一座位、同一未来日期与时间段；
2. 触发：同时（或尽量同时）向 `/student/reservations` 提交两条预约请求；
3. 观测：统计数据库中该座位该时段的有效预约条数、`reservation_slots` 唯一约束是否生效、HTTP 响应是否出现 500；
4. 判定：**恰好 1 条成功**、另一条被拒绝且提示冲突、无重复占位、无 500；重复运行多次结果稳定；
5. 记录：把实际结果、重复次数、是否出现不稳定现象写入本节与 TC-CONC-01 行。

> 若并发测试失败，应按“缺陷记录”流程登记，不得直接修改测试以回避问题。

## 8. 结论填写指引

### 8.1 结论用词规范

仅允许以下三种结论：

| 结论 | 适用条件 | 必须附带的说明 |
|---|---|---|
| **通过** | 必测点全部执行且全部通过；无未关闭的严重缺陷 | 附 pytest 原始输出与执行时间 |
| **有条件通过** | 核心用例通过，存在已知非严重缺陷或部分环境未覆盖 | 列出未覆盖项与已知缺陷编号 |
| **不通过** | 存在未修复的严重缺陷，或核心用例失败 | 列出失败用例与缺陷编号，说明阻塞原因 |

> 禁止使用“基本通过”“预计通过”“应该没问题”等模糊表述；**禁止在未运行时填写“通过”**。

未关闭缺陷：{数量与编号，或“无”}。
